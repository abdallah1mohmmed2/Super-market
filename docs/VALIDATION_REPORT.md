## تغطية الخادم

- مسارات الصحة والإعدادات والجلسة، وتطابق معرّف الطلب بين الرؤوس والجسم.
- رفض التوكن غير الصالح والمستخدم غير المهيأ، وعدم منح صلاحيات بناءً على مدخلات العميل.
- إرسال الحفظ نفسه عشر مرات متزامنة: إصدار واحد وسجل تدقيق واحد في PostgreSQL.
- اختلاف المحتوى مع المفتاح نفسه يعيد 409.
- تكرار الباركود يعيد 409، ويرجع المعاملة دون منتج أو مفتاح عملية أو سجل تدقيق جزئي.
- تعديل تعريف صنف برصيد 24 يبقي الرصيد 24، مهما كانت الكمية المرسلة في الطلب.
- تعارض الإصدارات، وعزل الفروع، ومنع الدور الذي يملك صلاحية القراءة فقط من الحفظ.
- سقف الصفحة 30 ثم صفحة متبقية، ومؤشر خاص بالفرع، وETag/304، والبحث والباركود.
- طلب CORS التمهيدي، ورفض الأصول غير المسموحة، وإضافة ترويسات CORS إلى أخطاء الطلبات من أصل مسموح.
- حد حجم الجسم، واشتراط UUID v4، ورفض حقول إضافية داخل الوحدات ونوع محتوى غير JSON.
- حد الطلبات، ورد 429، وترويسة Retry-After.
- توليد مفتاح RSA اختباري بطول 2048 بت وفحص توقيع حقيقي؛ ورفض التلاعب بالتوقيع أو مطالبات aud/iss/sub/exp/iat/auth_time أو الخوارزمية none.
- تخزين مفاتيح JWK مؤقتاً، ورفض المصادقة عند فشل خدمة المفاتيح. لا تستخدم الاختبارات شبكة Firebase الحقيقية.

## تغطية عميل HTTP والعقود

تثبت اختبارات العميل أن إعادة المحاولة تحافظ على المفتاح والجسم والتوكن ومعرّف الطلب، وأن تعارض 409 لا يعاد تلقائياً. وتتحقق من ETag وسقف الصفحة والتوقف بعد ثلاث محاولات عند انتهاء المهلة. تثبت اختبارات العقود حفظ السعر النصي الكبير دون تقريب، وعدم قابلية قائمة الوحدات للتعديل، وبقاء معرّف الطلب.

## حدود النتيجة

- لم تنفذ أو تختبر واجهات Flutter والتخزين المحلي وتقارير PDF بعد، ولم تُبنَ حزم Android أوWindows أوWeb.
- لم تُنفذ الدورات اللاحقة، ومواصفات الدورة الرابعة غير مرفقة.
- لم تُقَس وعود 10ms/15ms أو p95 في الإنتاج، ولا توجد نتيجة اختبار حمل k6 بعد.
- لم يُختبر إرسال FCM باستخدام مشروع حقيقي، ولم يُنشر خادم إنتاج.
- أُضيف Dockerfile، لكن بناء صورة Docker لم يُشغّل محلياً.
- الأرقام السابقة نتائج محلية؛ تُوثق حالة GitHub Actions البعيدة بصورة منفصلة بعد رفع الفرع.
